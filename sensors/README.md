# recognizer-sensors

Recognizer's shipped sensors. Each reads the repository's cached scans and its working tree and writes one findings file (`schema/findings.schema.json`); `crap` and `mutation` also write an overlay (`schema/overlay.schema.json`). A sensor is one complete run: `crap` and `mutation` run the repository's tests themselves, so they execute the repository's code in its working tree.

```sh
recognizer-sensors NAME [--repository P] [--commit C] [--output F] [--settings JSON]
```

`--repository` defaults to `.`, `--commit` to `git rev-parse HEAD`, `--output` to stdout and `--settings` to `{}`. Exit status is `2` for an unknown or missing name, a `--settings` that is not a JSON object or holds a bad or unknown key, a missing repository, no commit and any argument error. `--version` prints the package version, which is also the findings file's `sensor.version`.

A repository registers a shipped sensor in `.recognizer/config.yaml` by name: `sensors: {duplication: {}}`. `recognizer` expands that to `recognizer-sensors duplication --repository {repository} --commit {commit} --output {output} --settings <the mapping as JSON>`.

Install with `uvx --from ./sensors recognizer-sensors` or `pipx install ./sensors`. The names a sensor knows are listed in `fixtures/sensors/shipped.json`.

A sensor reports nothing for a file its grammars do not parse: a file with an extension no grammar covers is skipped, and so is a function whose syntax tree has an error node.

## crap

Scores each function or method by change risk: `crap = cc^2 * (1 - coverage)^3 + cc`, as crap4j and unclebob/crapper do (references, never dependencies). `cc` is the cyclomatic complexity from the syntax tree: one plus each `if`, `elif`, loop, `case`/`when`/match arm, `catch`/`except`, conditional expression, `&&`/`||` (`and`/`or` in Python) and, in TypeScript, each `??` and `?.`. Coverage is the share of a function's instrumented lines (merged by path) that were hit.

It runs the test suites listed under `tests:` in `.recognizer/config.yaml` in the same run, each in the user's login shell, so it runs the repository's code in the working tree. `modified` is taken before the tests start. With no `tests:` list it does not run: it exits `2` with `coverage unavailable: no test suites are configured; add a tests list to .recognizer/config.yaml` and leaves a prior overlay untouched. `recognizer-sensors crap --preflight` prints one gap, `crap:no-test-suites`, when the list is absent and none when it is set.

| setting | default | meaning |
| --- | --- | --- |
| `threshold` | `30` | a number above 0; a function at or above it is a warning |
| `overlay` | `.recognizer/cache/overlays/crap.json` | relative path inside the repository the overlay is written to |

The `tests` list reaches the sensor as `--settings` JSON, put there by `recognizer` from the config's top-level `tests:` key; it is not a setting a user writes under `sensors.crap`, and `test_command` and `coverage` are no longer `crap` settings.

**Test suites.** Each suite has `name`, `language`, `directory`, `command`, an optional `activate` and `env`, and `coverage {path, format}` (`lcov` or `jacoco`); a TypeScript suite also names its `runner`. A suite runs as `$SHELL -ilc 'cd <directory> && <activate> && <command>'` (`/bin/zsh` when `SHELL` is unset) with the suite's `env`, from the repository, one after another in list order, with its output in `.recognizer/cache/coverage/last-run.log`. The sensor adds no flag, plugin, wrapper or environment variable, creates no environment and installs nothing. After a suite ends, its report is the files matching `<directory>/<coverage.path>` modified at or after the moment the suite started; nothing is deleted and an older report never counts. A suite whose language has no scan in the run is skipped. A suite that fails after writing its report keeps its coverage (diagnosis `tests-failed`); a suite that leaves no fresh report, or an empty one, gives `coverage-unavailable` naming the suite; a scanned language with no suite has unknown coverage and a `coverage-unavailable` diagnosis naming the language.

Unknown is never zero: a function whose file has no entry in the report has no `coverage` or `crap` overlay value and warns only when `cc` alone is at or above the threshold (summary `CRAP at least <cc>`). Findings are warnings with the id `crap:<module>::<function>` and the fix pattern `simplify-or-test`. The sensor also writes the overlay with the metrics `complexity`, `coverage` and `crap`, all at member granularity, keyed `module::function` or `module::Class.method`.

A failing test run does not end C.R.A.P. A suite's report is read even when the suite fails, and the findings document then carries a `diagnosis` with code `tests-failed`, the count of failing tests where the output names them (`failing.count`), at most five names (`failing.names`) and a line such as `3 tests failed, so coverage may read low`. When a suite leaves no fresh report, or its program does not start, C.R.A.P. reports complexity alone (every function has unknown coverage, so findings read `unknown coverage, CRAP at least <cc>` and the overlay holds only `complexity`) and the document carries a `diagnosis` with code `coverage-unavailable` and a line such as `coverage unavailable: the api suite left no coverage report at <path>; see .recognizer/cache/coverage/last-run.log`. Mutation instead refuses: it exits `2` and writes no document, before any mutant, when a suite's coverage run exits non-zero (code `tests-failed`, naming up to five failing tests: `the test suite fails before any mutation: tests/test_orders.py::test_refund and 2 more`) or no coverage can be produced (code `coverage-unavailable`).

A refusal prints exactly two stderr lines: a line starting `recognizer-reason` and a space, followed by the diagnosis as JSON (`code`, `line`, optional `fix` and `failing`), then the plain `line`. Every other exit-2 path (bad settings, an unknown sensor) prints one plain line. The combined output of every command is in `.recognizer/cache/coverage/last-run.log`. The commands run in the sensor's own process group, so killing the group ends them.

## duplication

Reports pairs and families of functions or methods in the same language whose structure is alike. A function is normalised (local names, parameter names, field names and literals become kind tokens; call names, operators and shape stay), every subtree down to depth 3 is hashed with SHA-1 and the set of hashes is the function's structural fingerprint. A pair is linked when the Jaccard similarity of the two sets is at or above `threshold`; each connected group of linked functions (a duplication family) is one finding, and a plain pair is a family of two.

| setting | default | meaning |
| --- | --- | --- |
| `threshold` | `0.82` | a number above 0 and at most 1 |
| `min_lines` | `4` | functions with fewer lines are skipped, and so are family members (integer >= 1) |
| `pair_min_lines` | `6` | a two-member pair is dropped unless its shorter member has at least `max(min_lines, pair_min_lines)` lines (integer >= 1) |
| `min_nodes` | `20` | functions with fewer syntax nodes are skipped (integer >= 1) |

Two shapes are skipped before fingerprinting, because same-shaped functions of this kind are rightly separate. A constructor shape is a body of only assignments whose right-hand side is a parameter or a literal: Python, TypeScript, Kotlin and C# `field = parameter` statements (plain `=` only), and in Rust the same statements or a single `Self { a, b: 1, c: param }` struct expression. An accessor shape is a body of one result (a `return`, or in Rust, Kotlin and C# an expression body or tail expression) that is a member access, subscript or call chain over a name or `self`/`this`, where every call argument and subscript index is a literal or `self`/`this`. A body with a branch, a local variable, an operator or a non-literal argument is neither, and is scored as before. A language's null (`None`, Kotlin `null`, Rust `None`) counts as a literal only where its grammar parses it as one: Kotlin `null` and Rust `None` do not.

Each finding is a warning on every member's module, with the fix pattern `extract-shared-function` and every member function as an evidence member with `file` and `lines`. A pair keeps the id `duplication:<a>|<b>`; a family of three or more is `duplication:<a>|<b>#<n>` (its first two members and the member count), its summary names every member, or reads `<n> methods of <prefix> share one structure` when all members are in one file under one qualified-name prefix, and its similarity is the lowest linking pair's. Findings are written largest first by lines duplicated (the sum of the members' line counts), then by id. Written with unclebob/dryer (0BSD) as the reference, never a dependency.

Cost: scoring is quadratic in the number of functions per language, narrowed by a size filter and an inverted index on fingerprints; a very large repository may take minutes. The sensor runs only when asked (`recognizer scan --sense duplication`), never on open.

## mutation

Mutates each covered function and runs the repository's tests against every mutant, as unclebob/mutator and clj-mutate do (references, never dependencies), then warns on each function with a surviving mutant, naming each mutation and its line (`line 2 >= to >`), with the fix pattern `strengthen-tests`. One run does it all: the coverage run, the mutants, and the writes.

Mutation reads the `tests` list the core hands it from the config's top-level `tests:` key, as C.R.A.P. does, and runs every command it starts in the user's login shell (`$SHELL -ilc 'cd <directory> && <activate> && <command>'`) with the suite's `env`, inside a copy of the repository. It builds no environment and installs nothing: each language mandates dev-only tools that the repository installs itself (`pytest` with `coverage` and `pytest-cov`; `vitest` with `@vitest/coverage-v8` or `@vitest/coverage-istanbul`, or `jest`; the Gradle wrapper with the JaCoCo plugin and its XML report; `cargo-llvm-cov` with the `llvm-tools-preview` component; `coverlet.collector` in each C# test project). A missing tool fails the run with the tool's own output in `.recognizer/cache/coverage/last-run.log`. With no `tests:` list it exits `2` with the C.R.A.P. sentence, and `recognizer-sensors mutation --preflight` prints one gap, `mutation:no-test-suites`. A file belongs to the suite of its language whose `directory` is the longest prefix of its path; a file under no suite is not mutated and has no overlay value, and a scanned language with no suite prints one stderr line and is not measured. Two suites of one language and directory are a settings error.

| setting | default | meaning |
| --- | --- | --- |
| `tests` | none | the suites, handed over by the core; never written under `sensors.mutation` |
| `carry` | none | repository-relative folders, with no trailing slash, that a copy takes although git does not list them (a venv, `node_modules`, build output); each entry names the exact folder, never a name matched at any depth, and nothing is carried by name when it is absent |
| `timeout_factor` | `10` | a mutant's timeout is `max(2, timeout_factor * baseline seconds)` of the baseline of the command that mutant runs; a timed-out run is killed |
| `max_workers` | the core count | integer >= 1, mutants run at once |
| `overlay` | `.recognizer/cache/overlays/mutation.json` | relative path the overlay is written to |
| `survivors` | `.recognizer/cache/mutation/survivors.json` | relative path the survivors file is written to |
| `record` | `.recognizer/cache/mutation/record.json` | relative path the mutation record is written to |
| `incremental` | `true` | `false` ignores the record and mutates every function; the record is still written |
| `max_minutes` | none | number above 0; no function starts once this many minutes have passed since the first mutant was handed to a worker (the coverage run is not counted) |

Before any mutant the sensor makes one Warm-up copy under `.recognizer/cache/mutation/work/` and runs each suite's own `command` in it, in list order, with the flag that records per-test contexts added for Python (`--cov-context=test`) and a trx logger for C#. A suite that exits non-zero refuses the run, with a stderr line beside the refusal naming `carry` when a folder the suite needs was not carried. A Python suite's `command` must end in the `pytest` invocation so the flag can be appended. An activated venv's editable install points at the original checkout, so a copy could import unmutated source: when the Python suite's coverage report names a source file inside the original repository but outside the Warm-up copy, the sensor stops before any mutant with `coverage unavailable: the <suite> suite imported <path> from outside its repository copy ...`; set `PYTHONPATH` in the suite's `env` to a path inside the repository (resolved inside the copy). The sensor never edits the config, the venv or the copy to fix it, and it cannot see an editable or path-linked dependency in another language.

The operators, one replacement each: `true`/`false` (`True`/`False` in Python), `==`/`!=`, `<`/`<=`, `>`/`>=`, `+`/`-`, `*`/`/`, `&&`/`||` (`and`/`or` and removing `not` in Python), and in TypeScript `===`/`!==` and `??` to `&&` (C# has no `??` site). Strings, comments, generics, unary minus, Rust dereference and a C# `#if` condition yield none, and neither does an uncovered line.

A failing coverage run or baseline writes nothing and exits `2` with the one-line sentences listed under `crap` (the baseline's output tail goes to `last-run.log`). A mutant is killed by a non-zero exit, a failure to start or a timeout, and survives on exit `0`. The sensor writes the survivors file and the record, then the overlay, then the findings. The overlay holds `killed`, `survived` and `uncovered` counts and `score = killed / (killed + survived)` (absent when nothing ran) per function, keyed `module::function`; a function with unknown coverage is absent. It removes a stale `.recognizer/cache/overlays/mutate.json` when it writes its overlay. Copies live under `.recognizer/cache/mutation/work/` and are removed as each mutant finishes; a run killed with `SIGKILL` leaves its copies behind. A run with the whole suite per mutant takes the suite's duration times the covered-site count over `max_workers`; with test selection each mutant takes only the duration of the test files that executed its line.

A timed-out mutant is a kill: it counts in `killed` and the score, is listed under `timeouts` in the survivors file and never under `survivors`.

**Test selection.** The coverage run also records which tests executed each line, and a mutant runs only the tests that executed the line its site is covered by (the greatest recorded line from the function's start up to the site), using only the mandated tools. Python runs `pytest -rfE <files>` on the test files named by the per-test contexts; the per-test contexts are read from the Warm-up copy's coverage data with coverage.py's data API, one source file at a time, dropping the empty context and everything after `|` or `::`, and a line whose names are not all existing files runs the whole suite. TypeScript has no warm-up: each mutant runs the suite's `runner` selection, `npx --no -- vitest related <file> --run` or `npx --no -- jest --findRelatedTests <file>`, with `--bail=1` or `--bail` once the baseline has passed and `--maxWorkers` when several mutants run at once. `vitest related` exits `0` when no test imports the file, so the first mutant of each file is preceded by one unmutated baseline run of its selected command, and a baseline whose output says `No affected test files found` (or that fails, as `jest` does) makes that file run the whole suite, with one stderr line naming the file. `npx --no` fails instead of downloading anything. Kotlin runs `./gradlew test --no-daemon --tests <class>` for the classes of the covering test files (grouped per Gradle project; `--no-daemon` on every Gradle command, so no daemon is left behind, and copies share the user's normal Gradle home); the pass reads the test classes the Warm-up copy's whole run listed under `build/test-results/test`, maps each to the one test file declaring it (by `package` line and top-level `class` or `object`), and adds one `./gradlew test --no-daemon --rerun --tests <classes> jacocoTestReport` run per test file; a class with no single test file or one failing run drops Kotlin selection for the run. C# runs `dotnet test --filter` with one clause per class (each ending in a dot, so a class never matches a longer name); the pass adds a trx logger to the whole run to list the test classes (the `**/TestResults/results_*.trx` files modified since it started; none found drops selection), maps each to the one `.cs` file declaring it (nested classes with `+`), and adds one `dotnet test --filter <classes>` run per test file; a class with no single test file, one failing run or a run that executed other classes than its filter names drops C# selection for the run. Rust runs `cargo test -p <package> --lib --bin <name> --test <name>` for the cargo test targets that executed the line (doctests are not run by a selected command); the pass reads the targets of the default workspace members from `cargo metadata --no-deps`, names each by its repository-relative source path, groups the unit tests inside source files as one unit per lib or bin target and hashes each group's test items as its in-file test hash (an in-file test edit reruns the sites its unit group covers), and adds one `cargo llvm-cov -p <package> --lib|--bin|--test <name>` run per target; a failed `cargo metadata`, a target outside the repository or named twice, or one failing run drops Rust selection for the run. Kotlin, Rust and C# select only when the language has exactly one suite and its directory is `.`; otherwise each mutant runs the whole suite with one stderr line (`<language> has N suites` or `<language> runs from <directory>`). A selection of more than 50 files, a selection of more than half the suite (the distinct test files across all recorded lines; it takes no baseline of its own) or a file name starting with `-` runs the whole suite. A selected command whose baseline fails falls back to the whole suite with one stderr line; a failing whole-suite baseline exits `2`. A mutant that only an unattributed side effect (a session fixture credited to the first file that used it) would have killed can survive; set `incremental: false` for a full verdict.

**Mutation record.** Beside the survivors file the run writes the record (version 3, tables plus ids; a record written with `selection: 2` is ignored, so the first run after the upgrade re-measures every site): top-level `files` holds each distinct `[path, hash]` pair once and `sets` each distinct set of `files` indices once, and per function, the sha256 of its body, one verdict per mutation site (`killed`, `survived`, `timeout`, or `null` for an uncovered site) and, per covered site, an index into `sets` for the test files that ran it (`ran`) and, for a kill, an index for the test files the runner reported failing (`killer`), each file with its hash in `files`; plus `support`, the hash of the shared fixture files (every test file that is neither a test entry nor a `conftest.py`), the sha256 of the record key (`{"suites": <the suites as parsed, in order>, "selection": 3}`, so a change to a suite's `env` or command changes it and `max_workers` does not), the commit as provenance and the identities the last run skipped. Each site is judged on its own: a killed or timed-out site is reused while its function's body hash and every file in its `killer` map, counting the `conftest.py` files on their paths, are unchanged by hash; a surviving site is rerun when a covering test file is new or changed; a covered site with no verdict is run for the first time. A change to a shared support file voids all reuse. A site with no covering test files (TypeScript, or dropped selection) records `ran: null` and is reused only while the hash of all test files is unchanged. Python mutants run with `-rfE` and `killer` is read from the `FAILED` and `ERROR` lines, falling back to `ran` when they are missing or name an unknown path. The same rule applies with and without a module scope: a function outside the scope is carried only when every covered site passes it, and otherwise has no result. A function that only moved keeps its verdicts and reports its new lines. A missing, unreadable or other-version record, or changed suites, means a full run. Known limit: a change to a callee or other production code, with the function's body and test files unchanged, leaves a stale verdict the rule cannot see, as does a test file the convention in `mutation/test_files.py` does not recognise; set `incremental: false` for a full re-verdict.

**Budget.** With `max_minutes` set, work is queued by function: the functions the last run skipped first, then the rest, each in identity order. A function is wholly reused, wholly mutated or skipped; one already running when the budget ends finishes, so a run can overshoot by up to one function per worker. A skipped function is absent from the overlay (unknown, never healthy), listed in the survivors file's `skipped` with reason `uncovered-by-budget`, and `complete` is `false`. The survivors file also carries `reused`, the number of reused functions, and `unmeasured`: `{"budget": <functions in skipped>, "no-covering-test": <functions with known coverage and mutation sites, none covered>}`. Every run prints `recognizer-sensors: mutation: <r> of <n> functions reused, <m> mutated, <k> skipped (uncovered-by-budget)` on stderr, then a line with the functions without a covering test and how many mutants ran a selection or the whole suite, and exits `0`. The coverage run is outside the budget, so a run can exceed `max_minutes` by its duration.

## thresholds

Reads every current overlay in `.recognizer/cache/overlays/` and writes one finding for each module or member whose value for a configured metric crosses its line. It measures nothing. The settings are a mapping from metric name to a line: `{above: N}` or `{below: N}` with an optional `severity` of `warning` (default) or `violation`, or the string `off` to switch a metric's line off.

| metric       | default line |
| ------------ | ------------ |
| `complexity` | above 10     |
| `coverage`   | below 0.6    |

There is no default for `crap` or `survived`: the `crap` and `mutation` sensors judge those, and a user may still name them. An entry replaces a metric's default whole. An `above` line fires at `value >= line` and a `below` line at `value < line`. A finding has the id `thresholds:<metric>:<key>` (the overlay's own key), the kind `thresholds.<metric>`, the principle `tests-cover-the-code` for `coverage`, `functions-stay-small` for `complexity` and the metric's name otherwise, the new `metric` field, and `evidence.measures` `{value, line}` with `evidence.producer` naming the overlay's producer. A violation ratchets in the baseline by its id.

An overlay of another commit, or an unreadable one, is skipped with a line on stderr. The first overlay by file name that declares a metric supplies all of its values. A key matching no scanned module is counted and skipped; a metric you named that no current overlay declares prints a line. `recognizer scan --sense` runs sensors in the config's order, so list `thresholds` after `crap` to judge that run's overlay.
